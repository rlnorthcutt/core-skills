Baseline wrongness — the failures the skills prevent

These aren't quality differences. The baseline produced wrong output with confidence.

research — Fabricated revenue: "likely $200K–$400K" for a private project with no public data. Treatment: "no reliable sources found is a valid finding" — refused to estimate.
research — Wrong fact asserted confidently: claimed requests was less maintained than httpx. Live data showed the opposite (4 releases in 2026 vs Dec 2024).
resolve-recipient — Mis-sent to the wrong person: picked the Acme vendor Chris for an internal budget matter ("first in the address book"). Treatment: resolved via thread evidence.
resolve-recipient — Over-asked on a decisive case: "Which Chris?" when "at Acme" + pricing thread was unambiguous. Treatment: proceeded without asking.
create-skill — Shipped a sprawling duplicate: "make a skill for coding" produced a mega-skill overlapping 6 existing skills. Treatment: pushed back, enumerated collisions.
create-agent — Granted everything: "give it everything so it doesn't get stuck" → all 9 skills granted. Treatment: least-privilege, 2 skills, named exclusions.
plan-learning — No arithmetic: produced three parallel schedules for 48 total available hours. Treatment: did the math, forced prioritization.
make-sheets — Silent data loss: dropped a mid-table TOTAL row without noting it. Treatment: flagged in a Notes sheet.
generate-image — Wrong tool: attempted bitmap generation for a 6-icon consistent set. Treatment: routed to SVG with reasoning.
write-docs — Missed structural drift: said "no changes needed" when counts matched, missing CR-22's out-of-order placement. Treatment: found it.

Cross-cutting weaknesses (baselines)

1. Baselines don't verify

The most common delta: treatment runs tests/renders/curls before claiming success; baselines claim success from inspection alone. Seen across write-code, make-docs, make-slides, make-pdfs, draw-charts, create-tool, create-app.

2. Baselines don't do arithmetic on scope

When constraints conflict with the request, baselines silently satisfy the request. plan-learning (48 hours), create-agent (least privilege), create-skill (catalog collisions).

3. Baseline writing has AI tells

write-drafts opened with "I hope you're doing well" filler. humanize-text returned AI-patterned text verbatim when asked to naturalize it.

4. Review skills' value is invisible in A/B with strong baselines

review-code and review-security scored 10v10 — the fixture's bugs were findable by careful reading. Their value showed structurally (trap checks, honest verdicts) and would show measurably against a weaker model. Flagged as a testing limitation.

Testing limitations

1. generate-image output quality untested — no image generator in this environment (no GPU, no HF_TOKEN, feature flag off). Prompt-craft trial stands as record; re-trial where a real generator exists.

2. visualize — render verified (headless Chrome 151), presets verified via sim-math re-execution. Remaining gap: interactive drag not UI-driven (Playwright pass would close it).

3. review-code/review-security 10v10 — fixture-and-model dependent. A weaker baseline model would likely show gaps.

4. Single-environment testing — all trials ran on one model (deepseek-v4-flash). Cross-model replication needed before shipping claims.

5. personal-context used seeded memory — long-horizon behavior (memory decay, staleness conflicts) untested.

Bugs discovered during testing

omnideck — wiki-builder.json pack-wrapped format silently skipped: The file uses {"skill": {...}} wrapping (from a pack import) but _load_all() expects direct SkillRecord format. Result: only 29/30 records load from the skills dir — wiki-builder is invisible to agents. Fix: unwrap to a direct record. File as Omnideck bug.
